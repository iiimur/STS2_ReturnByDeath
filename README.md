# ReturnByDeath（死亡回归）

这是一个面向 Slay the Spire 2 `v0.111.0` 的纯 DLL mod。它没有 Godot 场景和 `.pck`，所以源码项目使用普通的 `Microsoft.NET.Sdk`，只引用游戏提供的程序集。

## 项目结构

```text
ReturnByDeath/
├── ReturnByDeath.csproj       # C# 项目、游戏 API 引用、自动复制规则
├── ReturnByDeath.json         # 必需的 mod manifest
├── README.md                  # 项目总览
├── Scripts/
│   ├── Entry.cs               # [ModInitializer] 入口、Harmony 初始化
│   └── ReturnByDeath.cs       # 按功能区组织的实现代码
├── Resource/
│   ├── 音效/                  # WAV/OGG 音效源文件
│   │   └── 惨叫/              # 惨叫音效源文件
│   ├── 视频/                  # OGV 视频源文件
│   └── 图片/                  # 图片源文件（含怠惰结局图、Re0标题图；封面图.jpg 不参与游戏运行）
│       └── 选项按钮贴图/      # 奥托事件按钮贴图源文件
```

构建时会把 `Resource/` 下的运行资源复制到 `游戏目录/mods/ReturnByDeath/` 根目录，保持 DLL 当前的加载路径不变。检查点、遭遇记录和日志是运行时生成文件，不属于可分发内容。

## 建议阅读顺序

1. `ReturnByDeath.json`：理解 mod ID、版本、依赖和 `has_dll`。
2. `Scripts/Entry.cs`：理解游戏如何找到并调用入口。
3. `Scripts/ReturnByDeath.cs` 顶部的 `#region`：了解功能分区。
4. `CheckpointStore` 和 `RecoveryFlow`：理解检查点保存、死亡合并和回归加载。
5. `EncounterJournalStore`：理解遭遇记录、回归重放和问号事件过滤。
6. 文件底部的 Harmony Patch：理解在什么生命周期节点修改游戏行为。

## 编译

在 `ReturnByDeath` 目录执行：

```bash
dotnet build ReturnByDeath.csproj -c Release
```

构建后会自动把 DLL、manifest 和 WAV 复制到本地 `mods/ReturnByDeath/`。游戏程序集只作为编译引用，不会被复制进 mod。

## 本地测试控制台命令

开启游戏开发控制台后输入：

```text
boss pride
map reveal
```

`boss pride` 只开启傲慢线；之后可自行使用原版 `act` 和 `room BOSS` 命令进入最终 Boss，用于测试傲慢开场演出和建筑师终局流程。`map reveal` 切换"全知之眼"：开启后本层地图全部节点与路径线直接可见（再输一次关闭），便于测试。

## 当前功能

- 新局初始最大生命为 86；第一层先古选项完成后生命固定为 4。
- 二、三层先古事件不再回血（原版回血被置为 0），也不额外扣血。
- 回归血量恢复为最近一次先古选项完成时保存的生命值；回归新增诅咒不会额外改变恢复血量。
- 选择先古选项后保存检查点。
- 正常死亡后回到最近检查点，并按规则添加 `GUILTY` 或 `Injury`；傲慢结局触发后回归不再添加任何诅咒，且每次回归血量与血量上限各 +1（跨回归累计）。
- 死亡前记录已探索的地图节点；回归后这些节点保持可见，保留上一条时间线的足迹。
- 获得卡牌与升级会立即增量写入检查点；死亡回归直接读取该检查点牌组，不再复制死亡时整副牌组，因此删牌与后续附魔会随时间线回滚。药水、最大生命、药水槽、金币和遗物仍回到检查点状态，能量与充能球槽成长继续保留。
- 记录并回放普通/精英遭遇预告；事件专属战斗不占用普通遭遇池。
- 莱茵哈鲁特可在火堆锻造升级，升级后移除所需的战斗数 +1；锻造之外的升级来源对它无效。
- 地图节点分三类显示：已探索节点（当前与既往时间线走过的房间）、探索中节点（当前所在与历代死亡/放弃的位置）、以及当前可选的下一批节点；Boss 节点始终显示（双 Boss 模式下两个都显示）；路径线显示走过的边与玩家在选择界面见过的路线（选路时记录，含未选择的分支），未探索区域内部的线一律隐藏。
- 战斗卡牌奖励在生成时快照；载入存档后奖励与 SL 前一致，不会因原版重掷机制而变化。
- 建筑师使用原版终局结算，不触发回归。
- 顶栏计时器旁显示不随死亡回归回档的总游玩时间（`当前时间 / 总时间`）；失忆回归后总时间从零重新计时。
- 已预留第三层首次死亡的“失忆回归”与死亡记忆面板代码，但当前版本暂未启用；在找回记忆的完整演出方案确定前，它不会影响正常游玩。
- 集成先古相关的欢迎、死亡和回归音效。
- 蕾姆事件：死亡回归回到休息过的火堆检查点且牌组含至少 2 张愧疚时，点击"放弃"触发（菜单自动关闭）；依次弹出三个带蓝色引言与专属音频的确认弹窗，最终可进入"怠惰"IF 线或从角色卡池的升级稀有卡中任选 2 张加入牌组。怠惰线中除建筑师外的战斗直接进入原生奖励结算（不显示敌人与战斗背景），事件失血/失去最大生命改为 0，自动开启全图与自由移动，且无法通过暂停或设置菜单放弃本局；建筑师终局仍完整保留。
- 蕾姆事件最终选择“不了”后，第一层 Boss 胜利会额外获得原版事件专属遗物“遗忘之魂”（每局一次）。
- 怠惰线第三层最后一个 Boss 胜利后，前往建筑师会先播放怠惰结局视频；视频结束后跳过建筑师对白与战斗，直接以胜利状态进入原版终局结算并播放怠惰专用死亡音效。

## 限制

这是影响游戏玩法的单人/假多人 mod。多人联机时应保证所有玩家使用兼容版本。游戏更新后应重新对照本地 `sts2.dll` 编译并进行加载测试。

## 源码结构与并行开发

源码按功能拆分在 `Scripts` 子目录中，最终仍编译为一个 `ReturnByDeath.dll`。`Cards` 存放新增卡牌，`Endings` 分开存放 Pride/Sloth 结局，`Events` 存放相关事件，`Persistence` 负责检查点与死亡回归，其他通用功能分别位于 `Combat`、`Map`、`Run`、`Audio` 和 `Presentation`。

普通构建仍会自动安装到游戏目录：

```bash
dotnet build ReturnByDeath.csproj -c Release
```

多个会话并行检查代码时应关闭自动安装，避免互相覆盖正在测试的 DLL：

```bash
dotnet build ReturnByDeath.csproj -c Release -p:InstallToGame=false
```
