# ReturnByDeath-死亡回归

这是一个面向 Slay the Spire 2 `v0.111.0` 的纯 DLL mod。它没有 Godot 场景和 `.pck`，所以源码项目使用普通的 `Microsoft.NET.Sdk`，只引用游戏提供的程序集。

## 项目结构

```text
ReturnByDeath/
├── ReturnByDeath.csproj       # C# 项目、游戏 API 引用、自动复制规则
├── ReturnByDeath.json         # 必需的 mod manifest
├── README.md                  # 项目总览
├── Scripts/
│   ├── Entry.cs               # [ModInitializer] 入口、Harmony 初始化
│   ├── ReturnByDeath.cs        # 旧链接与源码索引
│   ├── Persistence/            # 检查点、死亡回归与卡牌继承
│   ├── Cards/                  # 莱茵哈鲁特、奥托、肃清等卡牌
│   ├── Relics/                 # IF 线路与事件遗物
│   ├── Events/                 # 先古、莱茵哈鲁特、奥托、蕾姆等事件
│   ├── Endings/                # 傲慢、怠惰、强欲、愤怒 IF 结局
│   ├── Combat/                 # 遭遇预告、代理战斗与战斗 UI
│   ├── Map/                    # 地图节点和路线显示
│   ├── Run/                    # 局内时间、奖励快照等通用机制
│   ├── Audio/                  # 音频替换与播放
│   └── Presentation/           # 视频、结局图与界面演出
├── Resource/
│   ├── 音效/                  # WAV/OGG 音效源文件
│   │   └── 惨叫/              # 惨叫音效源文件
│   ├── 视频/                  # OGV 视频源文件
│   └── 图片/                  # 图片源文件（含怠惰结局图、Re0标题图；封面图.jpg 不参与游戏运行）
│       └── 选项按钮贴图/      # 奥托事件按钮贴图源文件
```

构建时会把 `Resource/` 下的运行资源复制到 `游戏目录/mods/ReturnByDeath/` 根目录，保持 DLL 当前的加载路径不变。检查点、遭遇记录和日志是运行时生成文件，不属于可分发内容。

## 建议阅读顺序

1. `ReturnByDeath.json`：理解 mod ID、版本、依赖和 `has_dll`。
2. `Scripts/Entry.cs`：理解游戏如何找到并调用入口。
3. `Scripts/` 下各功能目录：按功能阅读对应实现。
4. `CheckpointStore` 和 `RecoveryFlow`：理解检查点保存、死亡合并和回归加载。
5. `EncounterJournalStore`：理解遭遇记录、回归重放和问号事件过滤。
6. 文件底部的 Harmony Patch：理解在什么生命周期节点修改游戏行为。

## 编译

在 `ReturnByDeath` 目录执行：

```bash
dotnet build ReturnByDeath.csproj -c Release
```

构建后会自动把 DLL、manifest 和 WAV 复制到本地 `mods/ReturnByDeath/`。游戏程序集只作为编译引用，不会被复制进 mod。

## 本地测试控制台命令

开启游戏开发控制台后输入：

```text
boss pride
boss sloth
boss greed
boss wrath
map reveal
ending 1～4
event 1～7
```

`boss pride/sloth/greed/wrath` 会直接开启对应 IF 线并发放该线路的完整奖励，但不播放进入结局的音效和羽化图；之后可自行使用原版 `act` 和 `room BOSS` 命令进入最终 Boss。`map reveal` 切换“全知之眼”：开启后本层地图全部节点与路径线直接可见（再输一次关闭）。`ending 1～4` 和 `event 1～7` 用于切换对应的 IF 成就状态，仅供本地测试。

## 当前功能

### 基本死亡回归逻辑

- 新局初始最大生命为 86；第一层先古事件完成后，生命值固定为 4。
- 二、三层先古事件不再回血，也不额外扣血；完成先古选项后会保存检查点。符合流程的休息处也会成为可回归的火堆检查点。
- 正常死亡后回到最近检查点，恢复检查点时的生命、药水、最大生命、药水槽、金币和遗物；能量与充能球槽成长继续保留。
- 每次死亡会按死亡次数推进 `愧疚`/`受伤` 的回归诅咒预算。回归新增的诅咒不会额外改变恢复生命值；具体 IF 线路会覆盖这条规则。
- 卡牌获得、升级和转换会增量写入检查点。死亡回归读取检查点牌组，因此死亡前临时删牌、附魔等变化会随时间线回滚。
- 战斗卡牌奖励在生成或重掷时快照；读档后恢复该快照，避免原版重掷机制改变 SL 前的奖励。
- 建筑师是整局真正的终点，建筑师流程使用原版终局结算，不触发死亡回归。

### 新增遗物

以下遗物只通过本模组的事件或 IF 线路获得，不进入原生商店、奖励和随机遗物池：

- `过去的苦痛`：每场战斗开始时获得 1 层虚弱。
- `现在的牺牲`：每场战斗开始时获得 1 层脆弱。
- `未来的骨骸`：每场战斗开始时获得 1 层易伤。
- `强欲之心`：不再获得回归诅咒；每次死亡回归后当前生命与最大生命各增加 239，最大生命上限为 114514，达到上限后仍会回满当前生命。
- `朋友的护符`：每场战斗第一回合将 1 张临时“奥托”加入手牌。
- `怠惰之心`：获得后进入怠惰 IF 线，开放全图自由移动并跳过普通战斗。
- `傲慢之心`：允许以 0 费打出 `愧疚`/`受伤`；打出后从 3 张升级牌中选择 1 张加入手牌，并在本回合免费。
- `愤怒之心`：本回合打出的牌不超过 1 张时，回合结束获得 999 格挡。

### 新增卡牌

- `莱茵哈鲁特`：0 费、固有、对所有敌人造成 799 点伤害；基础经过 5 场战斗后自动从牌组移除。只能在火堆锻造升级，每次升级使移除所需战斗数增加 1；其他升级来源不会作用于它。
- `奥托`：0 费、保留、消耗的特殊技能牌；本回合获得力量并击晕所有敌人，只在奥托相关事件或遗物中临时生成，不进入卡池。
- `肃清`：愤怒 IF 线的无色稀有攻击牌，1 费造成 99 点伤害；升级后为 0 费。带有“永恒”，只通过愤怒线获得。

### 事件触发

- `莱茵哈鲁特`：第一层尚未在火堆休息、牌组至少有 1 张 `愧疚`，且检测到玩家即将无法承受敌方回合伤害时触发。事件会拦截结束回合，生成并自动打出莱茵哈鲁特；本场战斗结束时最多把 1 张 `愧疚` 转换为该卡。
- `奥托`：第二层、已从艾姬多娜事件取得 `过去的苦痛`、牌组至少有 3 张 `愧疚`，且本局尚未触发过奥托事件时，点击暂停/设置中的“放弃”触发。播放视频后可接受或拒绝奥托。
  - 接受：获得 `朋友的护符`，回满生命并清除牌组及战斗牌堆中的 `愧疚`/`受伤`；之后每场战斗第一回合获得临时 `奥托`。
  - 拒绝：播放拒绝视频并回归到检查点；第二层受伤预算达到 5 后可开启隐藏的艾姬多娜入口。
- `艾姬多娜`：第二层先古事件完成并存档后，地图图例出现沙堡入口。根据当前生命和已取得的试验遗物分阶段开放三次试验；每次试验取得 1 件对应遗物，取得遗物后会写入检查点。拒绝奥托后的隐藏入口不要求完成第二层先古事件。
- `蕾姆`：死亡回归落在已经休息过的第一层火堆检查点、牌组至少有 2 张 `愧疚`，且当前不在 IF 线路时，点击“放弃”触发。事件只可触发一次，流程支持保存退出后从当前弹窗继续。

### IF 结局

- `傲慢 IF`：莱茵哈鲁特被其他效果主动从牌组移除后进入。获得 `傲慢之心`，并播放傲慢结局触发演出；第三层建筑师使用专属三句对白和终局音效，玩家攻击保留演出但实际造成 0 点伤害。
- `怠惰 IF`：蕾姆事件最终选择“好的”，或取得 `怠惰之心` 后进入。全图开放、自由移动，除建筑师外的战斗直接进入原生奖励结算，暂停/设置菜单不能放弃本局；第三层 Boss 胜利后播放怠惰结局视频，跳过建筑师战斗并进入胜利结算。
- `强欲 IF`：在艾姬多娜事件最后选择 `强欲之心`，不实际承受该选项的致命伤害。获得 `强欲之心` 并清除诅咒预算；第三层第二次死亡，或第三层第一个宝箱房点击“前进”时，直接转为胜利结算。
- `愤怒 IF`：蕾姆“不了”分支获得的那张升级稀有牌被主动移出牌组后进入。获得 `愤怒之心` 和 2 张 `肃清`；建筑师只保留一段专属对白，随后播放愤怒结局音效并完成原版终局结算。
- 各 IF 线路互斥；进入一条线路后，其他线路的入口会失效。

### 成就系统

- 成就跨局全局保存，不会因死亡回归清除。
- 主菜单“百科大全”底部新增“IF 成就”入口，分为“结局成就”和“事件成就”，复用原版遗物收集界面展示。
- 结局成就：傲慢、怠惰、强欲、愤怒。
- 事件成就：莱茵哈鲁特救援、接受奥托、拒绝奥托、艾姬多娜的过去/现在/未来试炼、蕾姆“不了”分支。

### 美术更新（遭遇预告、第二时间线等）

- 遭遇预告：记录普通战斗、精英战斗、问号和商店的历史内容，并在地图/运行界面以原版历史记录风格展示；地图节点悬浮时会联动高亮对应预告。事件专属战斗不会错误消耗普通遭遇序列。
- 地图可见性：地图显示为已探索节点、当前/历代探索中的节点和下一批可选节点；Boss 节点始终显示。已走过的路线以及在选路界面见过的分支会保留，未探索区域的内部路线隐藏。
- 真实总时间：顶栏计时器显示 `当前时间 / 总时间`；死亡回归丢失的时间会累计到总时间，不会随检查点回档。新局会清零。
- 第二时间线/失忆回归：失忆状态和记忆面板代码已实现，但第三层第一次死亡触发失忆回归的入口目前暂未启用。普通死亡记录仍会保存为独立的“生命片段”，点击左上角头像可打开原版风格的记忆面板，使用左右箭头查看不同死亡记录、地图历史、死亡牌组和时间。
- 先古、回归、各 IF 结局、奥托和蕾姆事件均接入专属图片、视频和音效；资源源文件位于 `Resource/`。

## 限制

这是影响游戏玩法的单人mod，不支持也不会支持多人联机。游戏更新后应重新对照本地 `sts2.dll` 编译并进行加载测试。

## 源码结构与并行开发

源码按功能拆分在 `Scripts` 子目录中，最终仍编译为一个 `ReturnByDeath.dll`。`Cards` 存放新增卡牌，`Endings` 分开存放 Pride/Sloth 结局，`Events` 存放相关事件，`Persistence` 负责检查点与死亡回归，其他通用功能分别位于 `Combat`、`Map`、`Run`、`Audio` 和 `Presentation`。

普通构建仍会自动安装到游戏目录：

```bash
dotnet build ReturnByDeath.csproj -c Release
```

多个会话并行检查代码时应关闭自动安装，避免互相覆盖正在测试的 DLL：

```bash
dotnet build ReturnByDeath.csproj -c Release -p:InstallToGame=false
```
